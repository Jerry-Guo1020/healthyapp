## 二、技术方案

### 分层架构

```
app/entry/src/main/ets/
├── common/          # 常量、日志、会话、存储、设备标识
│   ├── Constants.ets      # BASE_URL、主题色、Storage Key
│   ├── AppGlobal.ets      # 全局 Context 持有（EntryAbility 注入）
│   ├── StorageUtil.ets    # preferences 键值持久化封装
│   ├── UserSession.ets    # 登录态（token/userInfo 内存 + 持久化）
│   ├── DeviceUtil.ets     # 设备标识（游客登录用，本地生成）
│   └── Logger.ets         # hilog 封装
├── model/
│   └── ApiModels.ets      # ApiResult<T> / AppLoginVo / AppUserInfoVo / CategoryVo / DishVo / AppPageVo<T> / BrowseHistoryVo
├── service/
│   ├── ApiClient.ets      # http 封装（baseUrl、Bearer 注入、JSON 解析、错误码/401 处理）
│   ├── AuthApi.ets        # 游客登录 / 发验证码 / 验证码登录 / 登出
│   └── BizApi.ets         # 分类 / 菜品分页 / 详情 / 收藏 / 浏览历史
├── components/
│   ├── DishCard.ets       # 菜品卡片（首页/收藏/历史复用）
│   └── EmptyView.ets      # 通用空态
└── pages/
    ├── Index.ets          # 启动页（会话恢复 + 路由分发）
    ├── LoginPage.ets      # 登录（手机验证码 + 游客一键登录）
    ├── MainPage.ets       # 底部四 Tab 主框架
    ├── DishDetailPage.ets # 菜品详情（收藏 / 记浏览）
    └── tab/               # HomeTab / FavoriteTab / HistoryTab / ProfileTab
```

### 页面设计（健康绿主题 `#00A86B`）

1. **启动页**：Logo + Slogan，恢复本地 token → 已登录进首页 / 未登录进登录页
2. **登录页**：手机号 + 验证码（倒计时）+ 登录按钮；下方「一键游客登录」为主路径
3. **首页**：搜索框 + 分类横向 Tab（全部/分类）+ 菜品列表（分页加载、空态提示）
4. **菜品详情**：封面大图 + 基本信息/标签 + 介绍/食材 + 营养指标 + 底部收藏按钮（记浏览）
5. **收藏 / 历史**：分页列表，Tab 切换自动刷新
6. **我的**：头像/昵称/游客标识 + 关于 + 退出登录

## 三、关键实现决策

- **Long 主键 → string**：后端 Jackson 已把雪花 ID 序列化为字符串，模型 `id/categoryId/parentId` 统一用 `string`，避免 JS 精度丢失
- **网络层统一封装**：`ApiClient` 自动拼接 `BASE_URL + /app/v1`、注入 `Authorization: Bearer`、`code===200` 判定、`401` 自动清会话、非 200 弹 `promptAction` Toast
- **登录态双层**：`UserSession` 内存态 + `StorageUtil`(preferences) 持久化；启动页 `init()` 恢复
- **游客登录复用**：`DeviceUtil.getDeviceId()` 首次生成随机设备号并持久化，后端据此建 `sh_user` 游客账号
- **Tab 自动刷新**：`MainPage` 通过 `AppStorage`('mainTabIndex') + 子 Tab `@StorageProp @Watch`，切到收藏/历史/我的时触发刷新
- **详情页状态拆分**：`favorite/favoriteCount` 用独立 `@State` 基本类型驱动 UI，避免 `@State` 嵌套对象属性变更不刷新问题
- **搜索触发**：用「搜索」文字按钮点击触发（避免 `onSubmit` 签名兼容隐患）

## 补记：首轮编译错误修复（DevEco hvigor）

用户首轮编译报 36 个错误，根因与修复如下：

1. **相对路径少一层**：`pages/tab/` 下文件误用 `../service` 等，正确应为 `../../service`；导致 Rollup 模块解析失败 + `cannot find module` + 派生 `any` 错误 + UI 组件语法不识别。→ 全部改 `../../`
2. **对象字面量**（`arkts-no-untyped-obj-literals`）：`AuthApi` 里 `{ deviceId }`/`{ phone }` 传 `object` 参数被禁止。→ 定义显式请求 class（`GuestLoginBody/SendCodeBody/LoginByCodeBody`）
3. **`tabIndex` 属性名冲突**：`@StorageProp('mainTabIndex') tabIndex` 与 `CustomComponent` 基类 `tabIndex` 成员冲突（类型 `(index) => CommonAttribute`）。→ 属性改名
4. **`AppStorage` 不可用**：SDK 6.1.1 的 `@kit.ArkUI` 不导出 `AppStorage`（提示改 `AppStorageV2`）。→ 放弃 `AppStorage/@StorageProp` 机制，改用 **`@Prop + @Watch` 父子通信**：`MainPage` 传 `active = (currentIndex === N)`，子 Tab 监听 `@Watch('onActiveChange')` 刷新
5. **`@Prop` 需本地初始化**：`DishCard.@Prop dish` 补默认值 `new DishVo()`
6. **`router.pushUrl` 的 `params` 嵌套字面量**：改显式 `DishDetailParams` 类

修复后应无 AppStorage/tabIndex 依赖，纯净 ArkUI 声明式实现。
