# 任务日志 2026-09-01-10 · 关闭登录验证码 + Turnstile 规划

## 一、目标

管理端登录页去掉图形验证码，后续由 Cloudflare Turnstile 人机认证替代（用户自行接入）。

## 二、已完成

### 1. 关闭图形验证码
- 改动：`api/ruoyi-admin/src/main/resources/application.yml` 的 `captcha.enable: true → false`。
- 前端无需改动：`login.vue` 用 `v-if="captchaEnabled"` 控制验证码框，后端 `/auth/code` 返回 `captchaEnabled:false` 后前端自动隐藏验证码框，且 Element Plus 不渲染的表单项不参与校验（`code` 不再 required）。
- 登录校验侧：`PasswordAuthStrategy.login()` 内 `if (captchaEnabled) validateCaptcha(...)`，关闭后跳过验证码校验。
- 验证：`GET /auth/code` 返回 `{"code":200,"data":{"captchaEnabled":false,"uuid":null,"img":null}}`；后端重启成功。

### 2. Cloudflare Turnstile 接入规划（用户自行实现）
- 前端：登录页加 Turnstile widget，登录提交时带 `turnstileToken`。
- 后端：`PasswordAuthStrategy` 校验 token（`https://challenges.cloudflare.com/turnstile/v0/siteverify`，secret + token + 可选 remoteip）。
- 与现 captcha 开关相互独立，不影响 App 端 JWT 登录。
- 部署环境变量：`TURNSTILE_SECRET_KEY`、`TURNSTILE_SITE_KEY` 注入（compose env）。

### 3. 本地 git 走代理
- 现象：代理软件监听 `127.0.0.1:7897` 但系统代理开关关闭，git 直连 github.com 443 失败。
- 解决：`git config --global http/https.proxy http://127.0.0.1:7897`，push 恢复稳定。
