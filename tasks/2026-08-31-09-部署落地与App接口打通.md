## 一、目标

## 二、已完成

### 1. 部署链路落定（pull 模型）
- 原方案：CI 的 deploy job 用 `appleboy/ssh-action` SSH 到国内服务器。
- 实测失败：GitHub 海外 runner SSH 到国内服务器在 **SSH 握手阶段被重置**（`kex_exchange_identification: Connection reset by peer`，见服务器 auth.log）。
- 最终方案：**服务器主动拉取**——CI 只构建+推送 GHCR 镜像；服务器 cron 每 3 分钟执行 `deploy/deploy.sh`（`docker compose pull && up` + 镜像清理）。
- 两个 workflow 已删除 deploy job，仅保留 build-and-push。

### 2. 服务器部署（/opt/shanheng）
- `docker-compose.yml`：生产版，改用 GHCR 固定小写镜像、避开被占端口（api 18080 / web 18081 / mysql 13306 / redis 16379）、强内存限制（mysql 500m/innodb 48M、api 900m/Xmx512m、redis 80m/32mb）。
- `.env`：随机生成 MySQL/Redis 密码。
- `deploy key`：服务器生成 `shanheng_deploy`（ed25519），公钥入 authorized_keys，私钥交用户填 secrets（后因改 pull 模型而不再被 CI 使用）。

### 3. 数据库导入
- 首次导入 `ry_vue_5.X.sql` 在 line 168 报 `Data too long for column 'nick_name'`（MySQL8 严格模式）并**中断**，sys_* 仅建 5 张。
- 解决：`deploy/init-db.sh` 关闭严格模式（`SET GLOBAL sql_mode='NO_ENGINE_SUBSTITUTION'`）后重建库重导。
- 结果：63 表（sys 21 + sj 22 + sh 15 + 其他5），`sys_user`=3、`sys_menu`=121、`sys_role`=3，完整。

### 4. 应用启动问题修复
- 报错 `Multiple garbage collectors selected`：镜像 ENTRYPOINT 自带 `-XX:+UseZGC`，compose 的 JAVA_OPTS 又加 `-XX:+UseG1GC` 冲突。
- 修复：JAVA_OPTS 改 `-XX:-UseZGC -XX:+UseG1GC`，启动成功（`Started DromaraApplication in 32s`）。

### 5. App 接口鉴权修复（关键）
- 报错：`/app/v1/auth/guest` 返回 401「认证失败，无法访问系统资源」。
- 根因：若依 `AllUrlHandler` 返回**应用内所有 Controller 路径**（含 shanheng 的 `/app/v1/**`），`SaRouter.match().check()` 因此也拦了 App 接口（并非只校验 DB 菜单）。
- 修复：`api/ruoyi-admin/src/main/resources/application.yml` 的 `security.excludes` 增加 `/app/v1/**`，App 端改走自有 JWT（`AppAuthInterceptor`）。
- 多租户确认：`PlusTenantLineHandler.ignoreTable` 在无租户上下文时直接放行，App 请求（无 sa-token 租户）不受多租户影响，`sh_*` 表无需加 tenant_id。

### 6. App 接口验证通过

- `GET /app/v1/categories`（带 Bearer token）→ `code:200`（数据空，待录）。
- `GET /app/v1/dishes?pageNum=1&pageSize=2` → `code:200` 分页结构正常（数据空）。

### 7. 管理端验证码修复
- 现象：前端登录页验证码不显示。
- 排查：后端 `/auth/code` 直连与走 nginx(18081) 反代均返回 200 + base64，链路正常；进一步解码 base64 magic bytes 为 `89504e47 0d0a 1a0a`（**PNG**）。
- 根因：后端验证码输出 PNG，前端 `login.vue`/`register.vue` 写死 `data:image/gif;base64,`，MIME 不匹配导致浏览器拒渲染。
- 修复：前端两处 `data:image/gif` → `data:image/png`，重新构建 web 镜像并部署，产物已确认为 `data:image/png;base64,`（5 处）。
- 管理端默认账号：`admin / admin123`（另有若依自带 test/test1 同样 admin123）。
