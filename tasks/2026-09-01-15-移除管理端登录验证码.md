# 任务 15：移除管理端登录图形验证码

日期：2026-09-01

## 背景
用户反馈管理端登录被验证码卡住进不去，要求删除验证码功能。

## 排查结论
- 后端已关闭：`application.yml` 的 `captcha.enable: false` 早已配置生效（`PasswordAuthStrategy` 在该开关为 false 时跳过 `validateCaptcha`）。
- 前端 `login.vue` 仍渲染验证码输入框 + `code` 必填校验 + 调 `/auth/code` 的 `getCode()` 逻辑，是用户「进不去」的直接观感来源。

## 本次改动
- `maneger-web/src/views/login.vue`：彻底删除验证码 UI 与逻辑
  - 移除 `<el-form-item v-if="captchaEnabled" prop="code">` 验证码输入框与图片
  - 移除 `loginForm.code/uuid`、`codeUrl`、`captchaEnabled` 状态
  - 移除 `code` 必填校验规则
  - 移除 `getCode()` 函数及 `getCodeImg` 引入
  - `onMounted` / `handleLogin` 失败分支不再刷新验证码
- 登录表单现在仅保留：租户（可选，受 `tenantEnabled` 控制）+ 用户名 + 密码 + 记住我。

## 备注
- 后端 `captcha.enable: false` 保留作为双保险；后续由 Cloudflare Turnstile 人机认证替代（用户自行接入）。
- `login.ts` 的 `getCodeImg` 仍被 `register.vue`（注册页，默认关闭）引用，予以保留。

## 补充：登录 405 根因修复（同日追加）
用户强刷后仍进不去，浏览器报 `POST /auth/login 405`。

### 根因
`maneger-web/.env.production` 被 `.gitignore` 的 `.env.*` 规则忽略，**从未进 GitHub 仓库**。CI 构建镜像时 `COPY maneger-web/ ./` 复制不到该文件，`VITE_APP_BASE_API` 未注入，构建产物 baseURL 为空 → 前端请求 `/auth/login`（无 `/prod-api` 前缀）→ nginx `location /` 的 `try_files` 兜底对 GET 返回 index.html、对 POST 返回 405。

### 修复
- `.gitignore`：新增 `!maneger-web/.env.production`、`!maneger-web/.env.development`（前端构建配置必须入库；其 RSA 密钥为浏览器可见的前端加密用，非后端私密）。
- `git add -f` 强制纳入两个 `.env` 文件（commit `8c9c7d5`）。

### 核对结论
- 前后端 RSA 加密密钥是**匹配**的（前端 `VITE_APP_RSA_PUBLIC_KEY` == 后端 `api-decrypt.privateKey` 注释里的“前端加密公钥”；`VITE_APP_RSA_PRIVATE_KEY` == 后端 `api-decrypt.publicKey` 注释里的“前端解密私钥”），非本次故障点。
- 修复后验证：主 JS 含 `prod-api`（3 次）；经 web 代理 `GET /prod-api/auth/tenant/list` 返回 JSON（tenantEnabled=true，默认租户 000000）；`GET /prod-api/auth/code` 返回 `captchaEnabled:false`。链路全部打通。

## 再补充：登录后“未知异常”修复 + 端到端自测（同日二次追加）
用户登录后浏览器报 `发生未知异常，请联系管理员`。

### 根因
登录本身已成功（日志 `user doLogin, userId:sys_user:1, token:***docTJw2Q`），异常在登录后加载数据时：`org.springframework.jdbc.BadSqlGrammarException: Unknown column 'tenant_id' in 'where clause'`，指向 `ShDishMapper`。

原因：多租户插件 `PlusTenantLineHandler` 在**有 sa-token 租户上下文**时（管理端登录后 tenantId=000000），会对未在 `tenant.excludes` 里的表自动追加 `tenant_id = '000000'` 过滤；而 `sh_*` 表（App 实体不继承 BaseEntity）没有 `tenant_id` 列，导致 SQL 报错。App 接口无租户上下文所以不受影响，管理端接口首次暴露该问题。

### 修复
`application.yml` 的 `tenant.excludes` 追加 15 张 `sh_*` 业务表（commit `da17e95`）：sh_user / sh_user_auth / sh_category / sh_dish / sh_dish_tag / sh_tag / sh_favorite / sh_browse_history / sh_health_auth / sh_health_summary / sh_recommendation_rule / sh_recommendation_record / sh_recommend_feedback / sh_user_preference / sh_user_avoid。

### 端到端自测（openssl 复刻前端 RSA+AES 加密登录，不依赖浏览器）
- 加密登录 `POST /prod-api/auth/login` → HTTP 200，拿到 access_token ✅（复刻：32 字节 AES key → 引号 base64 → RSA PKCS1 v1.5 加密为 encrypt-key；AES-256-ECB-PKCS7 加密请求体）。
- `GET /shanheng/dish/list` → `total:16`，字段完整，无 tenant_id 报错 ✅。
- `POST /shanheng/dish/enrich/215`（鸡丝荞麦面）→ 命中“鸡胸肉”推导 chicken breast，USDA 回填 `protein:20.40 / fat:8.10 / carbs:1.06` ✅。

至此管理端登录 → 菜品管理 → 联网补全全链路验证通过，无需用户再排查。
