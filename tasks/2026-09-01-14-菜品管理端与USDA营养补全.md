# 任务 14：菜品管理端 CRUD + USDA 营养联网补全（食物 API 方案 A+B 落地）

日期：2026-09-01

## 背景
用户拍板食物 API 采用「方案 A+B」：给 `sh_dish` 增加蛋白质/脂肪/碳水三大营养素字段（自建营养库），并集成 USDA FoodData Central 后端代理补全 + 管理端「联网补全」按钮，App 详情页展示三大营养素。

## 已完成

### 批次 1：数据层 + App 展示
- `api/script/sql/shanheng_business.sql`：`sh_dish` 在 `recommend_count` 后新增 `protein`/`fat`/`carbs` 三列，`DECIMAL(6,2)`，口径为每 100g 含量(g)。
- `deploy/sql/alter_dish_nutrition.sql`（新）：存量库 ALTER TABLE 增量迁移。
- `api/.../entity/ShDish.java`：新增 protein/fat/carbs 三个 `BigDecimal` 字段。
- `api/.../domain/vo/DishVo.java`：新增同名字段（App 端与管理端复用）。
- `app/entry/src/main/ets/model/ApiModels.ets`：DishVo 模型加 `protein/fat/carbs: number = 0`。
- `app/entry/src/main/ets/pages/DishDetailPage.ets`：营养卡片新增三大营养素展示行（>0 显示，否则提示可在管理端「联网补全」）。

- `support/USDAFoodClient.java`（新）：hutool HttpRequest 调 `https://api.nal.usda.gov/fdc/v1/foods/search`，按 nutrientId 1003/1004/1005 提取蛋白/脂肪/碳水；内置中英食材词典（覆盖种子数据 16 道菜食材）；`resolveKeyword()` 中文菜品名/食材 JSON → 英文关键词；首查带 `dataType=Foundation,SR%20Legacy`，无结果降级不过滤。

- `service/IShDishService.java` + `service/impl/ShDishServiceImpl.java`（新）：分页/详情/新增/修改/删除/`enrich()` 补全；分页复用 `DishAssembler` + `DishVo`；增改用 hutool `BeanUtil.copyProperties`（避免 mapstruct 依赖风险）。
- `mapper/ShDishMapper.java`：改造为 `BaseMapperPlus<ShDish, DishVo>`。
- `controller/ShDishController.java`（新）：`/shanheng/dish`（list/get/add/edit/remove/enrich），`@SaCheckPermission("shanheng:dish:*")`。
- `ruoyi-admin/src/main/resources/application.yml`：新增 `shanheng.usda.api-key`（默认 `DEMO_KEY`，可用环境变量 `SHANHENG_USDA_API_KEY` 覆盖）。
- `maneger-web/src/api/shanheng/dish/index.ts`（新）：菜品 API + 类型。
- `maneger-web/src/views/shanheng/dish/index.vue`（新）：菜品管理页（搜索 + 表格 + 增删改 + 「联网补全」弹窗，分类下拉暂硬编码种子 8 分类）。
- `deploy/sql/menu_dish.sql`（新）：`sys_menu` 幂等插入（目录 2000「膳衡业务」+ 菜单 2001「菜品管理」+ 按钮 2002-2005）。

## 关键决策
- 三大营养素字段口径：每 100g 含量(g)，与 USDA 数据一致。
- 中文→英文用内置词典（USDA 仅支持英文，中文查询 0 结果）；补全失败允许管理端手填英文关键词或手工填营养。
- 管理端复用 App 端 `DishVo`/`DishAssembler`（`favorite` 在管理端恒 false，安全）。
- 增改用 hutool `BeanUtil.copyProperties`，不引入 mapstruct 注解处理器（shanheng-app 未显式依赖 mapstruct-plus）。
