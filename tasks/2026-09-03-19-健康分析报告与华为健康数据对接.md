## 一、目标

用户希望「对接华为健康（Health Service Kit）数据 + 卡片式详细展示 + 健康数据分析并联动饮食推荐」。

拆解为三件事：

1. **健康数据分析**：后端把健康摘要拆成逐项指标评级 + 综合评分 + 饮食建议，并联动智能推荐。
2. **卡片式界面**：App「健康」页从简单摘要升级为「分析卡 + 指标网格卡 + 华为同步卡」。
3. **华为健康数据对接**：Health Service Kit 真实接入骨架（一般权限数据可落地）。

### 分析规则（HealthAnalyzer）

| 指标 | key | 评级阈值 | 建议示例 |
| --- | --- | --- | --- |
| 今日步数 | steps | <4000 需关注 / 4000-6000 一般 / 6000-8000 良好 / 8000-10000 良好 / ≥10000 优秀 | 久坐较多建议散步、补充蛋白质 |
| 昨晚睡眠 | sleep | <6h 需关注 / 6-7h 一般 / 7-9h 良好 / ≥9h 优秀 | 保证 7 小时、助眠食物 |
| 静息心率 | heartRate | 55-70 优秀 / 50-80 良好 / 80-100 一般 / 其它 需关注 | 少油少盐、深海鱼坚果 |
| 压力水平 | stress | 低=优秀 / 中=良好 / 高=需关注 | 镁/B 族维生素 |
| 活动量 | activity | 少=一般 / 适中=良好 / 充足=优秀 | 控制热量、优质蛋白 |

- 综合评分 = 各指标得分平均（四舍五入）。
- 综合评级：≥85 优秀 / ≥70 良好 / ≥55 一般 / 其它 需关注。
- 饮食建议：收集 level≥3 指标的针对性饮食建议拼接，无则给通用建议。
- 推荐复用 `IAppRecommendService.recommend()`（scene=HEALTH_ANALYSIS），生活动记录合理。

### 新增接口

`GET /app/v1/health/analysis` → `R<HealthAnalysisVo>`

无健康摘要时返回 `hasData=false` + 引导文案，前端据此显示空态。

### 卡片式界面结构（HealthTab）

1. **健康分析卡**：综合评分（大字 + 分色）+ 评级徽章 + 一句话结论 + 饮食建议条。
2. **指标网格卡**：2 列 Grid，每项含图标/名称/数值/单位/评级徽章/进度条/建议。
3. **华为运动健康同步卡**：同步按钮 + 步数/卡路里/距离展示 + 同步结果提示。
4. **手动记录卡**：保留原「睡眠/压力/活动」三档录入 + 上报推荐。
5. **为你推荐**：保留。

### 华为健康数据（华为 HealthServiceKit）关键结论

- `@kit.HealthServiceKit` 导出 `healthStore` 与 `healthService`。
- 核心 API：
  - `healthStore.init(context: common.Context)`
  - `healthStore.requestAuthorizations(ctx: common.UIAbilityContext, req)`
  - `healthStore.aggregateData(req)` —— 聚合统计（步数/卡路里/距离）
- 数据类型常量 `healthStore.healthDataTypes.DAILY_ACTIVITIES`。
- 字段 `healthStore.healthFields.DailyActivitiesAggregation`：step/calorie/distance 均为 `{sum}`。
- 聚合请求 `AggregateRequest` 必填 `startLocalDate/endLocalDate`（MM/DD/YYYY）、`dataType`、`metrics`（`{step:['sum'],...}`）、`groupBy`（`{unitType: GroupUnitType.DAY, duration:1}`）。
- **权限分级（关键约束）**：
  - **一般权限**：步数 / 卡路里 / 距离 / 运动记录等 —— **个人开发者可在 AGC 申请**，本轮已落地同步代码。
  - **受限权限**：心率 / 睡眠 / 压力 / 血氧等 —— **需企业开发者资质 + 受限权限审核**，本轮以上「手动录入」兜底。

### ArkTS 严格模式要点（沿用前序结论）

- 类型 `healthStore.AuthorizationRequest / AggregateRequest / AggregateResult / AggregateMetrics` 直接以 `healthStore.xxx` 命名空间类型访问。
- `BusinessError` 从 `@kit.BasicServicesKit` 导入，只做 `e as BusinessError` 断言，不 `new`。
- `getHostContext(): common.Context | undefined`（来自 `@ohos.app.ability.common`），判空后传入 `init/requestAuthorizations`。
