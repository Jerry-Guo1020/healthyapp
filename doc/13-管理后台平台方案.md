# 13 · 管理后台平台方案（RuoYi-Vue-Plus）

## 一、结论

采用 **RuoYi-Vue-Plus**（dromara 社区增强版，基于 Spring Boot 3.x + JDK 17 + MyBatis-Plus + sa-token + Vue3），作为**单后端底座**：

- `api/`：统一后端 = RuoYi-Vue-Plus 后端模块 + 新增 `shanheng-app` App 业务模块。
- `maneger-web/`：只放管理端前端（Vue3），构建后 Nginx 托管，对接 `api` 后端。
- 数据库：单库，若依 `sys_*` + 膳衡业务 `sh_*`。

**为什么是 RuoYi-Vue-Plus 而不是官方 RuoYi-Vue**：官方主线停留在 Java 8 / Spring Boot 2.5，Plus 已升级到 Boot 3 / JDK 17 / MyBatis-Plus / sa-token，满足"保持单后端 + 现代技术栈"两个诉求。

> 风险提示：Plus 是社区增强版（非华为/若依官方），迭代快、结构可能与官方原版不同。开工前锁定一个稳定 release tag，并以该版本的仓库结构为准。

## 二、工程结构（api/ 内）

RuoYi-Vue-Plus 各版本模块有差异，以锁定版本的仓库结构为准，大致如下：

```
api/
├── pom.xml                  # 父 POM
├── ruoyi-admin/             # 启动模块（依赖 shanheng-app）
├── ruoyi-framework/         # 框架：sa-token、配置、Redis、MyBatis-Plus
├── ruoyi-system/            # 系统模块：sys_* 表
├── ruoyi-common/            # 通用工具
├── ruoyi-generator/         # 代码生成器
└── shanheng-app/            # 新增 App 业务模块
    ├── controller/          # /app/v1/**
    ├── service/  mapper/  entity/
    ├── dto/
    └── security/            # App JWT 过滤器
```

`maneger-web/` 只放管理端 Vue3 前端，与后端分离部署。

## 三、认证与账号体系

| 端 | 路径 | 认证 | 账号表 |
| --- | --- | --- | --- |
| 管理端 | `/login`、`/system/**`、`/monitor/**`、`/tool/**` | sa-token（Plus 默认） | `sys_user` |
| App 端 | `/app/v1/**` | JWT | `sh_user` |

实现要点：
1. 管理端沿用 Plus 的 sa-token 登录与拦截器。
2. App 端复用 sa-token 的 JWT 插件（配置独立 token 风格 / 登录类型），或自写 JWT 过滤器，按 `/app/v1/**` 放行。
3. `sys_user`（后台运营）与 `sh_user`（App 用户）完全分离。

## 四、管理端功能模块

| 模块 | 说明 |
| --- | --- |
| 系统管理 | 若依内置：用户、角色、菜单、部门、岗位、字典、参数、通知、日志 |
| 菜品管理 | `sh_dish` CRUD，图片上传 R2，上下架/审核状态流转，标签/分类关联 |
| 分类管理 | `sh_category` 树形 CRUD，排序，首页快捷入口标记 |
| 标签管理 | `sh_tag` CRUD |
| 推荐规则管理 | `sh_recommendation_rule` CRUD，条件/动作/分值/理由模板配置，启停 |
| 用户管理 | 查看 `sh_user`、账号状态、华为绑定、健康授权状态（只读，可禁用） |
| 健康摘要记录 | 只读查看 `sh_health_summary`（保护数据完整性，不提供修改） |
| 推荐记录 | 只读查看 `sh_recommendation_record` + 反馈统计 |
| 内容审核 | 菜品 status：0 草稿 / 3 待审核 / 1 上架 / 2 下架 |
| 数据统计 | 推荐次数、收藏 Top、热门分类、用户增长 |

## 五、数据职责约定（单后端内的模块边界）

| 表 | App 模块（shanheng-app） | 管理端（若依 + 代码生成器） |
| --- | --- | --- |
| `sys_*` | ❌ 不碰 | ✅ 读写 |
| `sh_category/sh_tag/sh_dish/sh_recommendation_rule` | 只读 | ✅ 读写 |
| `sh_user/sh_health_summary/sh_recommendation_record/sh_favorite/sh_browse_history` | ✅ 读写 | 只读（查看/统计） |

## 六、实施步骤

1. 拉取 RuoYi-Vue-Plus 稳定 release，后端模块放入 `api/`，管理端前端放入 `maneger-web/`。
2. `ruoyi-admin` 启动模块增加对 `shanheng-app` 的依赖。
3. 新建 `shanheng-app` 模块，配置 App JWT（sa-token JWT 插件或自写过滤器），暴露 `/app/v1/**`。
4. 用代码生成器连接 `sh_dish/sh_category/sh_tag/sh_recommendation_rule` 表，生成管理端 CRUD + Vue3 页面。
5. 改造通用上传为 Cloudflare R2（预签名 URL 直传或后端中转）。
6. 推荐规则管理页：条件 JSON 编辑器 + 标签下拉 + 理由模板。
7. 统计页：基于 `sh_recommendation_record`、`sh_favorite` 聚合 SQL。

## 七、注意事项

- `sh_health_summary` 只读，管理端不可修改（合规红线）。
- 管理端操作日志用内置 `sys_oper_log`。
- App 端与管理端共用 Redis：验证码 key 加前缀区分，避免冲突。
- 数据库全库备份（`sys_*` + `sh_*` 同库）。
- **锁定 RuoYi-Vue-Plus 版本**：升级需先在测试环境验证，不追 latest。
