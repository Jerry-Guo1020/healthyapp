# 07 · 华为服务接入方案

## 一、Account Kit 登录接入

### 1.1 登录方式选型

| 方式 | 能力 | 适用对象 | 本项目优先级 |
| --- | --- | --- | --- |
| 华为账号一键登录（LoginWithHuaweiIDButton 组件，QUICK_LOGIN） | 华为官方按钮组件，点击后返回 UnionID + 授权码，可取手机号 | **仅企业开发者**（需申请 quickLoginAnonymousPhone 权限） | P1 已落地（unionID 直登） |
| 华为账号普通登录（授权码模式） | 跳转华为登录页 | 个人/企业 | P1 预留 |
| 手机号验证码登录 | 自有体系 | 所有 | P0 主用 |
| 游客模式 | 免登录浏览 | 所有 | P0 |

> **关键结论**：一键登录（取手机号）仅企业开发者可申请；普通华为账号登录（openid + profile 授权码模式）个人/企业均可用。当前 App 以“华为账号一键登录（unionID 直登）+ 普通华为登录 + 游客”为主，短信验证码已取消。

### 1.2 授权码模式登录流程（企业资质到位后启用）

```
1. App 调 Account Kit SDK 发起登录
2. 用户在华为登录页完成授权
3. App 拿到 Authorization Code
4. App → 后端 api：POST /app/v1/auth/huawei-login { code }
5. 后端用 code + client_id + client_secret 向华为 OAuth 服务器换 access_token
6. 后端用 access_token 调华为用户信息接口，获取 UnionID / OpenID / 手机号
7. 后端做注册/账号合并：
   - 按 union_id 查 sh_user_auth → 有则登录
   - 华为手机号与已有手机号账号一致 → 合并绑定
   - 无则创建新用户
8. 后端签发本系统 JWT 返回 App
```

### 1.3 账号合并规则

| 场景 | 处理 |
| --- | --- |
| 华为 UnionID 首次登录 | 创建新用户 + 绑定记录 |
| 华为手机号 = 已有手机号用户 | 绑定到已有用户 |
| 同一用户多次登录 | 返回已有用户 JWT |
| 解绑华为账号 | 保留手机号登录，删除绑定记录 |

### 1.4 降级方案

| 异常 | 兜底 |
| --- | --- |
| 未安装 HMS Core | 引导安装，或直接走验证码登录 |
| 华为账号未登录 | 引导登录华为账号，失败则验证码登录 |
| 一键登录失败 | 降级为华为普通登录，再降级验证码 |
| 用户拒绝授权手机号 | 仅获取 UnionID 建账号，不绑定手机号 |
| 企业资质未过 | 暂不展示华为登录按钮，只走验证码 + 游客 |

### 1.5 授权码登录落地实现（已实现，个人可用）

> 短信验证码需短信服务商（有费用）已放弃；采用华为账号**授权码模式**（个人开发者免费、无需企业资质）。一键登录（ID Token 静默）仍需企业资质，后置。

**后端接口**：`POST /app/v1/auth/huawei-login`（`HuaweiLoginBo{code, state}`）

处理流程（`AppAuthServiceImpl.huaweiLogin`）：
1. 用 code + client_id + client_secret 向后端代理（`HuaweiAccountClient`）换 access_token
2. 用 access_token 取华为用户信息（open_id / union_id / display_name / head_picture_url / phone_number）
3. 按 union_id 查 `sh_user_auth`（auth_type=HUAWEI）
   - 已有绑定 → 直接登录
   - 无绑定 → 新建 `sh_user` + 绑定 `sh_user_auth`；若华为返回手机号且已存在同手机号用户则合并账号
4. 签发自有 JWT 返回 App（走 `AppLoginVo`）

**后端配置**（`application.yml` → `shanheng.huawei.*`）：
```yaml
shanheng:
  huawei:
    client-id: ${SHANHENG_HUAWEI_CLIENT_ID:}
    client-secret: ${SHANHENG_HUAWEI_CLIENT_SECRET:}
    token-url: https://oauth-login.cloud.huawei.com/oauth2/v3/token
    userinfo-url: https://oauth-login.cloud.huawei.com/rest.php?nsp_svc=GOpen.oauth2.user.getTokenInfo
```

**前端实现**：
- `service/HuaweiAuthService.ets`：封装 `authentication.createAuthorizationWithAuthorizationCodeRequest` → execute 拿 authorizationCode；`HUAWEI_CLIENT_ID` 留空待填。
- `pages/LoginPage.ets`：「华为账号登录」按钮 → `onHuaweiLogin`：SDK 拿 code → `AuthApi.huaweiLogin` → 存 session 进主页。

**接入步骤（需用户操作）**：
1. 注册华为开发者账号并实名认证
2. AppGallery Connect 创建 HarmonyOS 应用 → 获取 AppID / client_id / client_secret
3. 开通「账号服务」(Account Kit)，勾选 scope：`openid` + `profile`
4. 真机调试用签名证书的 SHA-256 指纹配置进 AGC
5. 后端环境变量填 `SHANHENG_HUAWEI_CLIENT_ID/SECRET`；前端 `HuaweiAuthService.HUAWEI_CLIENT_ID` 填同值
6. 未配置时后端返回明确业务错误（不会 500），App 侧提示登录失败

### 1.6 一键登录落地实现（已实现，企业权限到位后启用）

> **关键纠偏**：华为一键登录**不能**用 `authentication.executeRequest(scope=quickLoginAnonymousPhone)` 直接拿 Authorization Code——该调用只返回**匿名手机号**（`response.data.extraInfo.quickLoginAnonymousPhone`），不返回 authorizationCode。旧版实现踩了此坑，导致“调起授权后登录失败、请求根本未到后端”。

正确流程（华为官方）：
1. `getQuickLoginAnonymousPhone()`：`executeRequest` + scope `quickLoginAnonymousPhone` + `forceAuthorization=false` → 拿到匿名手机号（打码形态“137****1234”，仅用于展示）
2. 展示 `LoginWithHuaweiIDButton` 组件（`loginType=LoginType.QUICK_LOGIN`，`Style.BUTTON_RED`）
3. 用户点击组件 → `onClickLoginWithHuaweiIDButton` 回调返回 `HuaweiIDCredential{ unionID, openID, authorizationCode }`
4. 前端直传 `unionId / openId` 到 `POST /app/v1/auth/huawei-login`（`HuaweiLoginBo{unionId, openId, ...}`），后端按 UnionID 查 `sh_user_auth` 绑定/自动注册，**无需 code 换 token**
5. （增强）后端用 `authorizationCode` 调 `/oauth2/v6/quickLogin/getPhoneNumber` 取完整手机号 + UnionID + OpenID，补齐手机号绑定

前端关键代码位置：
- `pages/login/LoginPage.ets`：`quickController`（`loginComponentManager.LoginWithHuaweiIDButtonController`）绑定 `.onClickLoginWithHuaweiIDButton` + `.setAgreementStatus`，勾选协议时同步 ACCEPTED/NOT_ACCEPTED
- `service/AuthApi.ets`：`huaweiQuickLogin(unionId, openId)`
- `service/HuaweiAuthService.ets`：普通授权码登录 `getAuthorizationCode()`（openid + profile）保留；旧 `quickLogin()` 已删除

常见错误码：

| 错误码 | 含义 | 处理 |
| --- | --- | --- |
| 1005300001 | 未同意协议 | 提示先勾选协议 |
| 1001502012 | 用户取消授权 | 静默，不提示 |
| 1001502014 | 未申请 scopes/权限 | 提示一键登录权限未开通 |
| 1001502001 | 华为账号未登录 | 引导登录华为账号 |

## 二、Health Service Kit 健康数据接入

### 2.1 数据获取原则

- ✅ 通过 Health Service Kit（Health Kit）读取，**不**直接当蓝牙设备读取手表原始数据。
- ✅ 用户显式授权，授权范围可单独勾选。
- ✅ 前端聚合为摘要再上传，**后端只存摘要不存原始数据**。
- ✅ 数据有延迟，产品不承诺实时/医疗级。

### 2.2 目标数据与权限

| 数据 | Health Kit 数据类型 | 敏感级别 | MVP |
| --- | --- | --- | --- |
| 步数/日常活动 | `steps` / `activity` | 一般 | ✅ P1 |
| 睡眠 | `sleep` | **受限** | ✅ P1 |
| 心率 | `heart_rate` | **受限** | P1 |
| 压力 | `stress` | **受限** | P1 |
| 血氧 | `spo2` | 受限 | P2 |
| 体温/HRV | 对应类型 | 受限 | P2 |

### 2.3 接入流程

```
1. AppGallery Connect 开通 Health Service Kit
2. 申请所需的数据权限（一般 + 受限），受限权限进入审核
3. 集成 Health Service Kit SDK
4. App 内发起授权（检查运动健康 App 是否安装）
5. 用户同意/拒绝授权
6. 授权成功 → SDK 读取数据
7. 前端聚合为摘要（今日步数、睡眠时长、压力等级等）
8. 上传后端 sh_health_summary
9. 后端结合摘要生成推荐
```

### 2.4 授权范围与取消

- 授权页支持按类型勾选（步数、睡眠、心率、压力）。
- App 内用户中心提供"取消健康授权"入口：调 SDK revoke + 后端 `sh_health_auth` 标记撤销 + 停止使用该摘要。
- 用户拒绝部分权限：只读取已授权部分，未授权字段置空，推荐引擎用"部分摘要"降级计算。

### 2.5 异常与降级

| 异常 | 兜底 |
| --- | --- |
| 未安装华为运动健康 App | 引导安装；未安装则禁用健康入口，提示仅可用菜单功能 |
| 用户拒绝授权 | 正常使用菜单功能，健康入口提示"授权后获得个性化推荐" |
| 只授权部分数据 | 用已授权数据计算，理由中说明"部分数据未授权" |
| 手表未同步 | 读取结果为空 → 用最近一次摘要；无则提示"暂无健康数据，先推荐常规菜单" |
| 无睡眠/压力数据 | 对应字段空，推荐规则跳过相关条件 |
| Health Kit 权限审核未过 | 前端提供"手动选择今日状态"降级入口（手动勾选：昨晚睡眠不足/压力大/今天运动多） |

### 2.6 手动健康状态降级（重要）

为对冲 Health Kit 审核周期，MVP 增加**手动健康状态**输入：
- 用户在推荐前手动选择：昨晚睡眠（不足/正常/充足）、今日压力（低/中/高）、今日活动（少/一般/多）。
- 后端把手动输入当作摘要来源 `MANUAL` 参与同一套规则计算。
- 好处：无手表用户也能体验“健康增强推荐”，且不依赖审核。

### 2.7 落地实现（已实现）

#### 2.7.1 后端健康分析

- 新增 `HealthAnalyzer` 分析引擎 + `GET /app/v1/health/analysis`。
- 把健康摘要拆成逐项指标（步数/睡眠/心率/压力/活动量）评级 + 综合评分 + 饮食建议，并复用智能推荐引擎输出关联推荐。
- 无健康数据时返回 `hasData=false`，前端展示空态引导。

#### 2.7.2 App 端华为同步（一般权限）

- 新增 `HuaweiHealthService.ets`，封装 Health Service Kit：
  - `healthStore.init(context)` 初始化；
  - `healthStore.requestAuthorizations(ctx, req)` 拉起系统授权；
  - `healthStore.aggregateData(req)` 聚合今日步数/卡路里/距离（数据类型 `DAILY_ACTIVITIES`，聚合字段 `step/calorie/distance` 取 `sum`）。
- 同步成功后把步数按阈值映射为活动量等级，融合进 `sh_health_summary`（source=HEALTH_KIT）上报。

#### 2.7.3 权限分级现状

| 数据 | 权限级别 | 现状 |
| --- | --- | --- |
| 步数 / 卡路里 / 距离 / 运动记录 | 一般权限 | ✅ 代码已落地，个人开发者可在 AGC 申请 |
| 心率 / 睡眠 / 压力 / 血氧 | 受限权限 | ⚠️ 需企业开发者资质 + 审核，当前以手动录入兜底 |

真机联调前置：AGC 开通「运动健康服务」，真机登录华为账号并具备运动健康数据源；受限权限数据待企业资质到位后再接入。

## 三、图标资源规范（预留替换）

### 3.1 现状与目标

- 当前搜索框 / 底部导航 / 我的页菜单使用 **emoji 占位**，统一收敛到 `common/Icons.ets`（含未来资源路径注释）。
- 目标：改为**本地 PNG/SVG 图标**（本地打包，不走 R2 对象存储）。

### 3.2 替换步骤

1. 图标放入 `app/entry/src/main/resources/base/media/`（如 `tab_home.png`）
2. 深色模式图标放入 `resources/dark/media/`，取**同名文件**即可随系统深浅色自动覆盖
3. 把 `AppIcons.xxx` 常量改为 `$r('app.media.tab_home')`，并将 `Text` 组件按需改为 `Image`

### 3.3 深浅色与选中态方案

- **深浅色**：`base/media`（浅色图）与 `dark/media`（深色图）同名覆盖，零代码判断
- **底部导航选中/未选中**：准备两套图标（`tab_home.png` 未选中灰 + `tab_home_active.png` 选中品牌绿），或单色 SVG 用 `Image.fillColor` 着色
- 首页 Tab 已在 `MainPage.tabBar` 增加 `index` 参数，选中态通过标题颜色/字重区分，图标位置已预留切换
- 我的页头像：登录态优先展示 `avatarUrl` 圆形 `Image`，未登录/无头像时用默认圆形占位（预留 `avatar_default.png`）

### 3.4 华为资源可用性

- media 图片支持格式：JPEG(.jpg) / PNG(.png) / GIF(.gif) / SVG(.svg) / WEBP(.webp) / BMP(.bmp)
- 资源目录：base + 限定词目录（颜色模式限定词 `dark` 用于深色模式同名覆盖）
- 单个图片资源建议 ≤ 1MB（DevEco 资源编译建议值）；图标类建议 SVG 或 48×48 / 96×96 小尺寸 PNG
- HAP 包总大小受应用市场上架规则限制，需以 AGC 发布规则为准；图标资源务必避免高清大图堆砌
