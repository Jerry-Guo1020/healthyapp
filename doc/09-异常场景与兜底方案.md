# 09 · 异常场景与兜底方案

> 原则：**健康数据是增强项，不是门槛**。任何健康数据相关异常都不能阻断菜单发现主流程。

## 一、异常场景矩阵

| 层级 | 异常 | 影响 | 兜底方案 |
| --- | --- | --- | --- |
| 登录 | 未安装 HMS Core | 无法华为登录 | 引导安装 / 改用验证码登录 |
| 登录 | 华为账号未登录 | 华为登录失败 | 引导登录 / 验证码登录 |
| 登录 | 一键登录失败 | 登录失败 | 华为普通登录 → 验证码登录 |
| 登录 | 验证码发送失败 | 无法登录 | 提示重试；短信服务商降级（备用通道/邮件） |
| 登录 | 用户拒绝手机号授权 | 无法绑定手机 | 用 UnionID 建账号，不绑定手机号 |
| 健康 | 未安装运动健康 App | 无法授权 | 引导安装；禁用健康入口，菜单功能正常 |
| 健康 | 用户拒绝授权 | 无健康数据 | 常规推荐；保留"手动健康状态"入口 |
| 健康 | 只授权部分数据 | 摘要不全 | 用部分摘要计算，理由注明"部分数据未授权" |
| 健康 | 手表未同步 | 读取为空 | 用最近一次摘要；无则常规推荐 |
| 健康 | 无睡眠/压力数据 | 对应规则失效 | 跳过对应规则，其余规则正常 |
| 健康 | Health Kit 权限审核未过 | 无法读取 | 启用"手动健康状态"降级 |
| 网络 | 请求超时/断网 | 页面无数据 | 友好提示 + 重试；首页/分类走本地缓存 |
| 后端 | 接口 500 | 功能不可用 | 全局异常处理返回统一结构；前端提示重试 |
| 后端 | 推荐引擎无候选菜品 | 推荐为空 | 返回兜底热销菜品 + "暂无匹配，为你推荐人气菜品" |
| 数据 | 菜品图片加载失败 | 视觉缺失 | 前端占位图 + 重试 |
| 数据 | R2 不可用 | 图片全挂 | 前端占位图；后端切备用图床 URL |
| 合规 | 用户取消授权 | 摘要失效 | 停止使用该摘要，推荐回归常规 |
| 合规 | 用户注销账号 | 数据需删除 | 匿名化/删除个人数据，保留统计脱敏数据 |

## 二、兜底实现要点

### 2.1 前端兜底

- **网络层统一拦截**：超时 10s，401 自动跳登录，5xx 提示重试，断网提示"网络异常"。
- **图片加载**：`Image` 组件 error 占位图。
- **健康入口三态**：未登录 → 引导登录；已登录未授权 → 引导授权；已授权但无数据 → 提示暂无数据并提供"手动状态"入口。
- **推荐空结果**：展示兜底热销菜品。

### 2.2 后端兜底

- **全局异常处理**：返回统一 `Result`，不泄露堆栈。
- **健康摘要容错**：摘要字段可空，规则引擎对空字段跳过。
- **推荐兜底**：候选集为空或过滤后为空时，按 `recommend_count`/`favorite_count` 取热销 Top N。
- **降级开关**：`sys_config` / `sh_config` 配置健康推荐开关，Health Kit 异常时可一键关闭健康增强，只走常规推荐。

### 2.3 数据兜底

- 健康摘要 24 小时过期：过期后重新拉取，拉取失败用最近一份并标记 `stale=true`。
- 推荐规则全部停用：使用默认打分（热度 + 时间 + 随机）兜底。

## 三、监控与告警（建议）

| 监控项 | 告警阈值 |
| --- | --- |
| 接口 5xx 率 | > 1% |
| 推荐接口 P95 | > 1s |
| 登录成功率 | < 95% |
| 健康摘要上传失败率 | > 10% |
| R2 图片加载失败率 | > 5% |
