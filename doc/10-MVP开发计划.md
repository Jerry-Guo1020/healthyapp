# 10 · MVP 开发计划

## 一、里程碑总览

| 里程碑 | 目标 | 预计周期 | 产出 |
| --- | --- | --- | --- |
| M0 基础设施 | 工程骨架 + CI/CD + 数据库 | 3 天 | git、docker-compose、建库建表、工作流跑通 |
| M1 管理端先行 | 若依后台 + 菜品管理 | 5 天 | 菜品/分类/标签 CRUD、R2 上传 |
| M2 业务后端 | api 核心接口 | 7 天 | 登录、菜单、收藏、推荐接口 |
| M3 鸿蒙前端 | App 核心页面 | 10 天 | 首页/发现/详情/推荐/用户中心 |
| M4 联调测试 | 真机联调 + 异常兜底 | 5 天 | 真机通过 + 验收 |
| M5 上线准备 | 合规 + 部署 + 种子数据 | 3 天 | 上架材料、生产部署 |

**总计约 5-6 周（单人业余时间）**。

---

## 二、迭代拆解

### M0：基础设施（3 天）

- [ ] `git init` + 分支规范 + `.gitignore`
- [ ] 初始化 `api/`：RuoYi-Vue-Plus 后端模块 + 新增 `shanheng-app` App 业务模块（验证码/JWT）
- [ ] 初始化 `maneger-web/`：若依 ruoyi-ui 前端（Vue）
- [ ] `docker-compose.yml`：MySQL 8.0 + Redis 7
- [ ] 执行 `doc/05-数据库设计.md` 的 `sh_*` DDL
- [ ] GitHub Actions：api 与 maneger-web 的 build 工作流
- [ ] Cloudflare R2 bucket 创建 + 密钥配置

### M1：管理端先行（5 天）

- [ ] 若依登录、用户、角色权限调通
- [ ] 代码生成器生成 `sh_dish`、`sh_category`、`sh_tag`、`sh_recommendation_rule` 的 CRUD
- [ ] 图片上传改造为 R2（预签名 URL / 后端中转）
- [ ] 录入 20+ 测试菜品，配置分类/标签/规则
- [ ] 内容审核字段（status 流转）

### M2：业务后端（7 天）

- [ ] 认证模块：验证码登录、游客登录、JWT、refresh
- [ ] 首页聚合 `/app/v1/home`
- [ ] 分类/菜品列表/详情/搜索
- [ ] 收藏、浏览历史
- [ ] 推荐引擎：规则解析 + 打分 + 理由生成
- [ ] 健康摘要上报/查询接口
- [ ] 用户偏好/忌口接口

### M3：鸿蒙前端（10 天）

- [ ] 网络层封装（JWT 携带、401 处理、统一错误）
- [ ] 首页（双入口 + 快捷入口 + 今日推荐）
- [ ] 菜单发现（分类页 + 列表 + 搜索 + 详情）
- [ ] 登录页（验证码 + 游客）
- [ ] 推荐页（推荐结果 + 理由 + 替代项）
- [ ] 用户中心（资料、偏好、收藏、历史、隐私）
- [ ] 手动健康状态入口（P0，先于 Health Kit）

### M4：联调测试（5 天）

- [ ] 按 `08-实体设备测试方案.md` 执行 T1/T2/E1-E12
- [ ] 修复缺陷，性能压测首页/列表
- [ ] 验收：数据库无原始健康数据、取消授权生效

### M5：上线准备（3 天）

- [ ] 隐私政策、用户协议
- [ ] 生产环境部署（Docker Compose + Nginx + HTTPS）
- [ ] 种子数据完善至 100+
- [ ] 提交华为 AppGallery Connect 上架（个人或企业资质按实际情况）
- [ ] 若涉及 Health Kit/Account Kit，提交权限申请

---

## 三、优先级原则

1. **先让"没有手表也能用"成立**：菜单发现 + 登录 + 推荐 + 管理端是 P0。
2. **健康数据后置**：先做"手动健康状态"降级，等权限审核过了再接 Health Kit。
3. **管理端先行于前端**：先有数据维护能力，前端才有内容可展示。
4. **每完成一个里程碑**：在 `tasks/` 追加日志。
