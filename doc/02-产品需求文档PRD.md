## 二、背景与目标

### 2.1 背景

- "今天吃什么"是普遍存在的日常决策难题，尤其在工作餐、宵夜、下午茶等场景。
- 华为手表/手环用户已积累步数、睡眠、心率、压力等健康数据，但这些数据目前只用于健康管理，未与饮食决策打通。
- 鸿蒙生态处于成长期，缺少"健康数据 + 饮食推荐"的原生应用。

### 2.2 产品目标

| 目标 | 衡量指标 |
| --- | --- |
| 解决选择困难 | 用户从打开 App 到获得推荐 ≤ 3 步 |
| 无手表可用 | 未授权健康数据的用户可完整使用菜单功能 |
| 健康增强 | 已授权用户获得带健康理由的推荐 |
| 合规安全 | 健康数据单独授权、可撤回、后端只存摘要 |

### 2.3 成功标准（MVP）

- 核心流程可用：游客浏览 → 登录 → 选场景 → 得推荐 → 收藏/反馈。
- 菜单数据 ≥ 100 条种子数据，覆盖 5 个餐次 + 10 个以上分类。
- 推荐引擎能按 3 类规则（场景/偏好/健康摘要）给出推荐理由。

## 三、用户画像

### 3.1 目标用户

| 画像 | 特征 | 核心诉求 | 使用路径 |
| --- | --- | --- | --- |
| A. 选择困难上班族 | 20-35 岁，每天纠结吃什么 | 快速出结果、按餐次/预算 | 首页 → 午餐 → 推荐列表 |
| B. 健康管理人群 | 关注睡眠/运动/体重，有手表 | 根据身体状态吃对东西 | 授权健康数据 → 今日推荐 |
| C. 华为生态用户 | 华为手机 + 手表/手环 | 原生体验、账号互通 | 华为登录 → 数据授权 |
| D. 口味探索者 | 喜欢按菜系/口味/标签浏览 | 分类全、搜索快、收藏 | 菜单发现 → 筛选/搜索 |

### 3.2 用户故事

- 作为上班族，我希望打开 App 就能看到"午餐吃什么"的推荐，这样我就不用纠结。
- 作为手表用户，我希望 App 知道我昨晚没睡好，给我推荐清淡暖胃的菜。
- 作为游客，我希望不注册也能先看看菜单，再决定要不要登录。
- 作为运营，我希望在后台维护菜品、分类和推荐规则，App 端实时生效。

## 四、功能需求

### 4.1 功能总览

| 模块 | 优先级 | 说明 |
| --- | --- | --- |
| 首页 | P0 | 双入口（健康推荐 / 菜单发现）+ 快捷入口 |
| 登录与账号 | P0 | 验证码登录、游客模式、华为登录（预留） |
| 菜单发现 | P0 | 分类、标签、搜索、详情 |
| 智能推荐 | P0 | 场景/偏好/健康摘要驱动的推荐 |
| 健康数据 | P1 | Health Kit 授权、读取、摘要上传 |
| 用户中心 | P0 | 资料、偏好、收藏、历史、隐私、取消授权 |
| 管理后台 | P1 | 菜品/分类/标签/规则/用户/统计/审核 |

### 4.2 首页（P0）

首页采用**双入口并列**设计：

```
┌───────────────────────────────┐
│  今日健康摘要（有手表才显示）    │
│  步数 8,200 · 睡眠 6.5h · 压力 低 │
├──────────────┬────────────────┤
│  健康推荐入口  │   菜单发现入口    │
│  "根据你的状  │  "今天想吃什么？" │
│   态推荐"    │                │
├──────────────┴────────────────┤
│  快捷场景：早餐 午餐 晚餐 下午茶 宵夜 │
│  快捷分类：粤菜 川菜 湘菜 轻食 低脂 高蛋白│
│  今日推荐吃什么（推荐卡片）        │
└───────────────────────────────┘
```

**功能点**：
- 今日健康摘要：无授权时显示"授权后可查看"，有授权时显示摘要卡片。
- 今日推荐吃什么：默认按当前时间推断餐次给 1-3 个推荐。
- 快捷入口：5 个餐次 + 6-8 个分类，可运营配置。
- 点击任一入口进入对应列表页。

### 4.3 登录与账号（P0）

| 登录方式 | 优先级 | 说明 |
| --- | --- | --- |
| 游客模式 | P0 | 不登录即可浏览菜单；收藏/偏好需登录 |
| 手机号验证码 | P0 | 主要登录方式，后端签发 JWT |
| 华为账号登录 | P1 | Account Kit，预留接口，企业资质后启用 |

**规则**：
- 游客浏览不弹登录；点收藏/设置偏好等操作时引导登录。
- 华为账号登录成功后，与手机号账号通过 UnionID/手机号做账号合并。
- 用户可随时解绑华为账号、取消健康授权。

### 4.4 菜单发现（P0）

**分类体系**（分类支持父子级）：

- 餐次：早餐、午餐、晚餐、下午茶、宵夜
- 菜系：广东菜、粤菜、川菜、湘菜
- 主食形态：米饭、面食、粥粉面
- 健康标签：轻食、低脂、低糖、高蛋白、暖胃、清淡
- 口味：辣味、重口味、甜品、饮品

**功能点**：
- 分类页：一级分类 + 二级分类筛选。
- 列表页：分页加载、按标签筛选、按热度/时间排序、搜索关键词。
- 搜索：菜名/食材/标签模糊搜索，搜索历史。
- 详情页：大图、食材、标签、营养信息（可选）、健康建议（可选）、收藏、推荐理由。
- 图片懒加载，使用 Cloudflare R2 存储。

### 4.5 智能推荐（P0）

**输入因子**：

| 类型 | 字段 |
| --- | --- |
| 场景 | 当前时间、餐次 |
| 偏好 | 口味偏好、菜系偏好、预算、健康目标（减脂/增肌/养胃/控糖） |
| 忌口 | 过敏原、忌口食材 |
| 健康摘要（可选） | 今日步数、睡眠时长/质量、压力值、静息心率、活动量 |

**输出**：
- 推荐菜品（1-3 个）
- 推荐理由（如"昨晚睡眠 5.8 小时，压力偏高，推荐清淡暖胃食物"）
- 健康建议（生活辅助，非医疗）
- 替代选项（2 个）
- 不推荐原因（如"含辣椒，与你忌口冲突"）
- 今日饮食提醒

**规则示例**：

| 条件 | 推荐策略 |
| --- | --- |
| 睡眠 < 6h 或 压力高 | 清淡、暖胃、低刺激 |
| 今日步数 > 1 万 或 运动量大 | 高蛋白、适量碳水 |
| 步数低、久坐 | 低脂、少油、易消化 |
| 目标=减脂 | 低脂、高蛋白、控碳水 |
| 目标=增肌 | 高蛋白、优质碳水 |
| 目标=控糖 | 低糖 |
| 忌口命中 | 直接排除含该食材的菜品 |

**推荐引擎实现**：MVP 采用**可配置规则引擎**（管理端配置规则，后端计算打分排序），不做机器学习。详见 `03-核心功能模块设计.md`。

### 4.6 健康数据（P1）

- 通过 Health Service Kit 读取：步数/日常活动、睡眠、心率、压力。
- 可扩展：血氧、体温、体重、情绪、HRV。
- 前端读取后聚合为**健康摘要**上传后端；后端**不保存原始健康数据**。
- 用户可查看授权状态、取消授权。

### 4.7 用户中心（P0）

- 用户资料（头像、昵称、手机号）
- 华为账号绑定状态
- 健康数据授权状态 + 取消授权入口
- 饮食偏好、忌口/过敏原
- 收藏菜品、浏览历史、推荐历史
- 隐私设置（清除缓存、注销账号）

### 4.8 管理后台（P1，若依）

- 菜品管理（增删改查、上下架、图片上传 R2）
- 分类管理、标签管理
- 推荐规则管理
- 用户管理、健康摘要记录管理
- 内容审核（菜品图片/文案）
- 数据统计（推荐次数、收藏数、热门菜品）

## 五、业务流程

### 5.1 无手表用户主流程

```
打开 App → 首页（游客可浏览）
  → 点击"午餐"或"菜单发现"
  → 浏览分类/搜索菜品
  → 查看菜品详情
  → 收藏（引导登录）
  → 登录（验证码）→ 设置偏好 → 获得个性化推荐
```

### 5.2 有手表用户主流程

```
登录 → 首页提示授权健康数据
  → 发起 Health Kit 授权（跳转华为运动健康）
  → 用户同意授权
  → App 读取健康数据 → 前端聚合摘要
  → 上传后端 → 后端生成推荐
  → 前端展示推荐 + 推荐理由
```

### 5.3 推荐请求流程

```
前端（App）
  ├─ 场景/偏好/忌口（本地 + 后端用户偏好）
  ├─ 健康摘要（Health Kit 读取后上传或使用最近一次摘要）
  └─ POST /app/v1/recommendations
        ↓
后端（api）
  ├─ 加载用户偏好/忌口
  ├─ 加载最近健康摘要
  ├─ 加载候选菜品（按餐次/分类）
  ├─ 规则引擎打分（排除忌口 → 场景匹配 → 健康匹配 → 偏好加分）
  └─ 返回推荐 + 理由
```

## 六、非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 首页接口 P95 < 500ms；列表分页接口 P95 < 800ms |
| 可用性 | 后端可用性 ≥ 99.5%（MVP 单机可接受） |
| 安全 | 所有接口 HTTPS；JWT 过期 ≤ 7 天；健康数据加密存储摘要 |
| 合规 | 隐私政策、用户协议、健康数据单独授权、可撤回、可注销 |
| 兼容 | HarmonyOS NEXT（API 24 / SDK 6.1.1）真机 |
| 数据 | 后端只存健康摘要，原始数据不上传、不落库 |
