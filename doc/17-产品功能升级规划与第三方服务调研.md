## 一、华为文档阅读理解

### 1.1 华为账号一键登录（获取手机号 + UnionID）

- **本质**：基于 OAuth2.0 + OpenID Connect 的授权登录，scope = `quickLoginAnonymousPhone`。
- **前端流程**：`createAuthorizationWithHuaweiIDRequest` 传 `scopes=['quickLoginAnonymousPhone']` → 拿到「匿名手机号 + Authorization Code」→ Apple 服务端用 `Client ID/Secret/Code` 调 `/oauth2/v6/quickLogin/getPhoneNumber` 获取「完整手机号 + UnionID/OpenID」。
- **与现有实现的区别**：

| 能力 | scope | 可获得 | 是否需要专属权限申请 |
| --- | --- | --- | --- |
| 一键登录（本文档） | `quickLoginAnonymousPhone` | 完整手机号 + UnionID | **要，企业开发者，审核约 3 工作日** |
| 华为账号登录（当前已实现） | `openid` + `profile` | UnionID + 昵称头像（无手机号） | 否（个人/企业均可用） |

- **硬性约束**（写申请文案的依据）：
  1. 应用须满足《常见类型移动互联网应用程序必要个人信息范围规定》中使用手机号的**必要业务场景**；
  2. **仅企业开发者可用**（个人开发者禁止一键登录）；
  3. 未申请权限报错 `1001502014`（应用未申请 scopes/permissions）。

### 1.2 Health Service Kit（运动健康服务）

- 基于华为账号 + 用户授权的运动健康数据开放平台；开放步数、心率等健康数据 + 专业运动数据。
- 支持 Phone/Tablet/Wearable/Lite Wearable；Phone/Tablet 仅限中国境内。
- 数据读取需用户授权（`healthStore.requestAuthorizations`），评论"一般/受限权限"分级（受限权限：心率/睡眠/压力/血氧，需企业资质 + 审核）。

## 二、华为账号一键登录「申请文案」（可直接粘贴使用）

> 用途：贴入 AGC「账号服务 → 华为账号一键登录」权限申请的「申请原因/业务场景说明」。

**应用信息**
- 应用名称：膳衡（健康饮食决策助手）
- 开发者：清远市粤叁科技发展有限公司
- 应用简介：面向华为用户的健康饮食平台，提供"吃什么"智能决策、健康数据驱动的饮食推荐、菜品社区分享三大能力。

**申请场景与必要性说明**

1. **账号体系是本应用核心功能的基础。** 本应用为用户提供菜品收藏、浏览历史、饮食偏好、忌口管理、健康摘要（经 Health Service Kit 授权获取的步数/睡眠/心率等）及个性化推荐记录等功能，上述个人数据均需绑定稳定账号方可跨设备、跨时段同步，必须建立用户账号体系。

2. **手机号是本应用用户账号的必要标识。** 依据《常见类型移动互联网应用程序必要个人信息范围规定》，本应用属于要求注册登录并提供个性化服务的工具类应用，手机号为必要个人信息。用户收藏的菜品、饮食偏好与忌口、健康数据均须归属到唯一手机号账号，才能保证数据正确与账号安全。

3. **华为账号一键登录能提升登录转化率与账号安全。** 接入一键登录后，用户无需手动输入手机号、无需等待短信验证码，一键完成注册/登录；同时华为侧返回经系统验证的手机号，可有效避免二次放号、身份伪造与短信验证码泄露等风险。

4. **华为 UnionID 与本应用手机号账号体系的合并需要获取手机号。** 用户通过华为账号登录与本应用手机号登录会形成两套账号，只有同时取得手机号与 UnionID，才能将两者绑定为同一用户，避免同一用户数据割裂、重复建档。

**数据合规承诺**
- 手机号仅用于账号注册、登录与账号关联，不用于任何其他用途；
- 获取手机号前将向用户明示用途并取得用户明确同意，并附《华为账号用户认证协议》；
- 用户可随时注销账号并删除全部个人数据；
- 严格遵守《个人信息保护法》《数据安全法》及 AppGallery Connect 隐私合规要求。

**结论**：恳请审核通过「华为账号一键登录」权限，以支撑本应用基于手机号与华为账号统一身份体系的个性化饮食健康服务。

## 四、"吃什么"推荐/抽签的开源与 API 调研

> 结论先行：**本项目"吃什么"的决策数据应坚持自有的 `sh_dish` 菜品库**（可控、带营养/标签/忌口/预算），外部 API 只做营养补全，不做"吃什么"决策。转盘抽签纯本地实现，无需外部 API。

### 4.1 随机抽签（转盘）——本地实现，无需 API

- 数据源：自有 `sh_dish`（已含早餐/午餐/晚餐等分类），按当前时段取对应分类随机抽取。
- 交互：ArkTS 转盘动画（`animateTo` 旋转 + 指针），结合忌口/偏好/预算/最近吃过做过滤后抽取。
- 可参考开源交互（GitHub 关键词）：`what-to-eat`、`今天吃什么`、`lunch-picker`、`roulette / wheel-of-fortune`（仅参考交互，不引依赖）。

### 4.2 菜谱/营养数据开源与免费 API

| 来源 | 免费额度 | 语言 | 用途定位 |
| --- | --- | --- | --- |
| **中国食物成分表**（卫健委/疾控公开数据） | 免费（离线） | 中文 | ⭐ 建议导入本地库做营养补全，一次导入永久离线用 |
| Open Food Facts | 免费（开源数据库） | 多语含中文 | 营养/食材补充 |
| USDA FoodData Central（现用） | DEMO_KEY 免费 / 注册 key 提额 | 英文 | 营养补全（已接入 `USDAFoodClient`） |
| TheMealDB | 免费 | 英文 | 带图片 + 做法步骤，可作"社区做法"参考数据源 |
| Spoonacular | 免费 150 次/天 | 英文 | 含**随机食谱接口**（random recipe）+ 营养，可参考"吃什么"随机逻辑 |
| Edamam | 免费额度 | 英文 | 营养分析 |

**结论**：中文中餐场景下，以上英文 API 均不直接适用于"今天吃什么中餐"决策，**真正落地的营养数据源= 中国食物成分表（本地导入）+ USDA（英文补全）**；推荐/抽签逻辑完全自研（已有 `RecommendEngine` + 待建转盘）。

## 五、新功能规划（本轮新增方向）

### 5.0 项目定位端正

**一句话定位**：膳衡 = 华为生态的「今天吃什么」健康饮食决策助手。

**三大支柱**：

| # | 支柱 | 解决 | 用户价值 |
| --- | --- | --- | --- |
| 1 | **社区发现**（小红书式卡片） | 不知道有什么可吃 | 看别人晒的吃的 + 做法，种草 |
| 2 | **转盘决策**（吃什么抽签） | 选择困难 | 按早/中/晚抽一道，一键出结果 |
| 3 | **健康推荐**（已有，深化） | 不知道吃啥才健康 | 结合步数/睡眠/心率等科学推荐 |

### 5.1 模块一：社区分享（小红书式卡片）

- **功能**：用户发布图文帖（照片 + 文字 + 标签 + 做法步骤），卡片流展示；点赞/收藏；关联系统菜品。
- **新增表**：`sh_share_post`（帖子：用户、照片、文字、标签、做法步骤、关联 dish_id、点赞数）、`sh_share_like`（点赞关系）。
- **后端**：发布/列表（分页卡片流）/点赞/收藏/详情/关联菜品。
- **前端**：首页新增「社区」Tab 或首页顶部入口，双列瀑布流卡片，点开看做法。
- **优先级**：P1（MVP 先做"发布 + 卡片流 + 点赞"，评论后置）。

### 5.2 模块二：吃什么转盘抽签

- **功能**：进入「今天吃什么」，自动识别当前时段（早/午/晚/夜宵）→ 从对应分类候选池抽一道（或一荤一素一汤组合）。
- **交互**：转盘指针旋转动画 → 落到菜品 → 展示卡片 + 「再抽一次」「就吃这个」「收藏/换一单」。
- **过滤**：复用忌口硬过滤 + 预算区间 + 偏好标签 + 最近吃过排除。
- **数据**：纯本地 `sh_dish`，无需外部 API。
- **后端**：新增 `GET /app/v1/dishes/random?mealType=BREAKFAST|LUNCH|DINNER`（或复用 dishes 筛选 + 前端随机），建议后端出"过滤后随机"保证忌口/预算生效。
- **前端**：新增「吃什么」转盘页面 + 首页入口。
- **优先级**：P1（交互是亮点，先做单道菜转盘，再做组合）。

### 5.3 模块三：健康数据推荐（已有，深化）

- 已完成：`HealthAnalyzer` 健康分析 + `RecommendEngine` 关联推荐 + 卡片式健康页。
- 深化方向：企业资质到位后，接手表受限权限数据（心率/睡眠/压力），扩展 `HuaweiHealthService` 读受限类型，使分析报告五项指标全部来自真实设备。

### 附：本轮关键结论

1. **华为一键登录** = 获取手机号的企业专属登录能力，需申请 + 3 工作日审核；当前已实现的「openid+profile 授权码登录」个人/企业均可用、无需申请。
2. **食物识别**：百度免费额度够用；彻底免费走 PaddleClas 本地；换国内大厂走腾讯云/阿里云。
3. **"吃什么"**：决策全靠自有 `sh_dish` + 自研引擎，转盘纯本地实现，不要依赖外部饮食推荐 API；英文 API（USDA/Spoonacular）只作营养补全。
4. **项目定位**：社区发现 + 转盘决策 + 健康推荐三大支柱，围绕"今天吃什么"。
