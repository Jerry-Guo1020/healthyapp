# 03 · 核心功能模块设计

## 一、模块划分

```
膳衡 App
├── M1 账号与授权模块（登录、JWT、华为账号绑定、游客）
├── M2 首页与场景模块（首页聚合、快捷入口、今日推荐）
├── M3 菜单发现模块（分类、标签、搜索、详情、收藏）
├── M4 健康数据模块（Health Kit 授权、读取、摘要）
├── M5 智能推荐模块（规则引擎、推荐记录、反馈）
├── M6 用户中心模块（资料、偏好、忌口、历史、隐私）
└── M7 运营管理模块（若依后台：菜品/分类/标签/规则/审核/统计）
```

---

## 二、M1 账号与授权模块

### 功能点

1. 手机号验证码登录：发送验证码（Redis 缓存，5 分钟有效，60s 防重发）→ 校验 → 注册/登录 → 签发 JWT。
2. 游客模式：后端生成匿名设备标识（设备 UUID），游客可浏览菜单，操作受限。
3. 华为 Account Kit 登录（预留）：Authorization Code 换 UnionID/OpenID/手机号 → 账号合并 → 签发 JWT。
4. 华为账号绑定/解绑。

### 关键设计

- 账号唯一键：`phone`（手机号）与 `union_id`（华为 UnionID）。
- 账号合并规则：华为登录的手机号与已有手机号账号一致则合并，否则创建新账号并绑定。
- Token：JWT（用户 ID + 角色 + 过期时间），Redis 存 refresh token。

---

## 三、M2 首页与场景模块

### 功能点

1. 首页聚合接口 `/app/v1/home` 一次返回：健康摘要卡片、双入口、快捷餐次、快捷分类、今日推荐。
2. 今日推荐：按当前时间推断餐次，调用推荐引擎生成 1-3 个结果。
3. 健康摘要卡片三态：
   - 未登录：引导登录
   - 已登录未授权：引导授权
   - 已授权：展示摘要（步数/睡眠/压力）
4. 快捷入口由管理端运营配置（分类表 `is_quick` 标记）。

## 四、M3 菜单发现模块

### 4.1 分类设计

分类表支持父子级（`parent_id`），顶层分类类型：

| 类型 | 一级分类 | 二级示例 |
| --- | --- | --- |
| 餐次 | 早餐/午餐/晚餐/下午茶/宵夜 | - |
| 菜系 | 广东菜、粤菜、川菜、湘菜 | - |
| 主食 | 米饭、面食、粥粉面 | - |
| 健康 | 轻食、低脂、低糖、高蛋白 | 暖胃、清淡 |
| 口味 | 辣味、重口味、甜品、饮品 | - |

> 注：广东菜与粤菜在产品上语义重叠，建议管理端归一为"粤菜"主分类，"广东菜"作为别名/标签，避免分类树冗余。详见 4.3 数据规范。

### 4.2 列表与搜索

- 列表接口支持：`categoryId`、`tagIds`、`keyword`、`sort`（hot/time）、`page`、`size`。
- 搜索：菜名、食材、标签模糊匹配（MySQL `LIKE` + 索引；数据量增大后接 Elasticsearch，MVP 不用）。
- 详情：大图（R2）、食材、标签、营养信息、健康建议、推荐理由。

### 4.3 菜品数据规范（运营录入）

每个菜品必填：
- 名称、分类（至少 1 个）、标签（1-5 个）、图片、食材列表
- 口味特征：辣度（0-3）、油度（0-3）、是否清淡、是否暖胃、是否易消化
- 营养标签（可选）：高蛋白、低脂、低糖等
- 价格区间（可选，用于预算过滤）

### 4.4 标签设计

标签表存两维：
- **口味/健康标签**：辣味、清淡、暖胃、高蛋白、低脂、低糖、重口味
- **场景标签**：减脂餐、增肌餐、养胃餐、控糖餐

## 五、M4 健康数据模块

### 5.1 数据流

```
华为手表/手环 → 华为运动健康 App 同步 → 膳衡 App 发起授权
→ Health Kit 读取数据 → 前端聚合摘要 → 上传后端 → 后端生成推荐
```

### 5.2 读取的数据与摘要字段

| 原始数据 | 摘要字段 | 后端存储 |
| --- | --- | --- |
| 步数 | today_steps | ✅ |
| 睡眠时长 | sleep_duration_min | ✅ |
| 睡眠质量 | sleep_quality_score | ✅ |
| 心率 | resting_heart_rate | ✅ |
| 压力 | stress_level | ✅ |
| 活动量 | activity_level | ✅ |

**原则**：前端只上传摘要（聚合后的数值/等级），不上传逐分钟原始曲线。后端 `sh_health_summary` 表只存摘要。

### 5.3 授权状态管理

- `sh_health_auth` 表记录授权时间、授权范围、状态。
- 用户取消授权：前端调 Health Kit 取消 + 后端标记失效 + 停止使用该摘要。
- 摘要有效期：最近一次授权后 24 小时内有效，超时重新拉取。

## 六、M5 智能推荐模块（核心）

### 6.1 推荐引擎架构

```
输入层（场景 + 偏好 + 忌口 + 健康摘要）
   ↓
过滤层（排除忌口命中、排除未上架、排除非当前餐次）
   ↓
打分层（规则引擎，按规则加减分）
   ↓
排序层（总分降序 + 随机扰动避免单一）
   ↓
输出层（推荐 + 理由 + 替代项 + 健康建议）
```

### 6.2 规则引擎设计

管理端配置规则，后端执行。规则结构：

| 字段 | 说明 |
| --- | --- |
| rule_name | 规则名 |
| conditions | 触发条件 JSON（如 `{"sleep_duration_min":{"lt":360}}`） |
| action | 动作（加分/减分/排除） |
| score | 分值 |
| tag_target | 命中的标签（如 清淡、暖胃） |
| reason_template | 推荐理由模板 |

### 6.3 规则示例

| 规则 | 条件 | 动作 |
| --- | --- | --- |
| 睡眠不足清淡 | 睡眠 < 360 分钟 或 压力=高 | 标签 清淡/暖胃 +10 |
| 睡眠不足忌刺激 | 睡眠 < 360 分钟 | 标签 辣味/重口味 -10 |
| 运动量高补蛋白 | 步数 > 10000 或 活动量=高 | 标签 高蛋白 +10 |
| 久坐低脂 | 步数 < 3000 | 标签 低脂/易消化 +10，重口味 -5 |
| 减脂目标 | 用户目标=减脂 | 标签 低脂/高蛋白 +8，油炸 -10 |
| 增肌目标 | 用户目标=增肌 | 标签 高蛋白 +10 |
| 控糖目标 | 用户目标=控糖 | 标签 低糖 +10，甜品 -10 |
| 忌口排除 | 忌口命中食材 | 直接排除 |

### 6.4 推荐理由生成

后端根据命中的规则 + 健康摘要生成人类可读理由，例如：
- "昨晚睡眠 5.8 小时、压力偏高，推荐清淡暖胃的菜品。"
- "今日步数已超 1 万，建议补充蛋白质。"
- "你设置了减脂目标，为你优先推荐低脂高蛋白菜品。"

### 6.5 推荐记录与反馈

- 每次推荐写入 `sh_recommendation_record`（含输入快照 + 输出结果）。
- 用户可对推荐结果反馈：喜欢 / 不喜欢 / 原因（太辣、太油、价格高等）。
- 反馈用于后续规则权重调整（v1.2+）。

## 七、M6 用户中心模块

- 资料：头像、昵称、手机号。
- 绑定状态：华为账号绑定、健康授权状态。
- 偏好：口味、菜系、预算、健康目标。
- 忌口/过敏原：多选（如花生、海鲜、辣椒、麸质）。
- 收藏、浏览历史、推荐历史：分页查看、删除。
- 隐私：取消健康授权、清缓存、注销账号（注销后匿名化处理个人数据）。

---

## 八、M7 运营管理模块（若依）

- 菜品管理：CRUD、上下架、图片上传 R2、标签/分类关联。
- 分类管理：树形分类 CRUD、排序、是否快捷入口。
- 标签管理：CRUD。
- 推荐规则管理：规则 CRUD、启用/停用、分值配置。
- 用户管理：查看用户、账号状态、健康授权状态（只读）。
- 健康摘要记录：只读查看（不提供修改）。
- 内容审核：菜品图片/文案审核流。
- 数据统计：推荐次数、收藏 Top、热门分类。
