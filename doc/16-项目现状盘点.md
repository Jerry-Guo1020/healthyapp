## 一、项目组成与已完成功能

「膳衡 App」= 鸿蒙 App 前端 + Spring Boot 后端（若依框架单后端）+ 若依管理平台，共三个运行单元。

### 1.1 总体架构

```
┌────────────────┐   ┌─────────────────────────────────┐   ┌─────────────────┐
│  鸿蒙 App       │   │  后端 api（RuoYi-Vue-Plus 单后端）│   │  若依管理平台     │
│  ArkTS 前端     │──▶│  ├─ ruoyi-admin（管理接口+系统）   │◀──│  maneger-web     │
│  (app/)        │   │  └─ shanheng-app（App 业务模块）   │   │  (Vue3 管理端)   │
└────────────────┘   └──────────────┬──────────────────┘   └─────────────────┘
                  HTTP /app/v1/**   │  MySQL(ry-vue) + Redis
                                     ▼
                          云服务器 43.139.91.62（Docker）
```

- **数据库**：MySQL `ry-vue` 库，共 63 张表（若依自带 ~48 张 + 业务 15 张 `sh_*` 表）。
- **认证双轨**：管理端 sa-token + `sys_user`；App 端自研 JWT + `sh_user`。
- **部署**：GitHub Actions 构建镜像 → GHCR → 服务器 cron 每 3 分钟 pull。端口：api `18080`，web `18081`。

### 1.3 后端（`api/`，RuoYi-Vue-Plus `shanheng-app` 模块）

业务接口统一前缀 `/app/v1/**`（sa-token 已放行），JWT 鉴权。

| 模块 | 端点 | 功能 |
| --- | --- | --- |
| 认证 auth | `POST /auth/send-code` `login-by-code` `guest` `huawei-login` `logout` | 登录闭环（验证码/游客/华为授权码，按 unionId 建绑用户） |
| 分类 categories | `GET /categories` | 分类树 |
| 菜品 dishes | `GET /dishes`（分页筛选）`GET /dishes/{id}` | 菜品列表/详情（含营养 protein/fat/carbs，支持预算过滤、忌口硬过滤） |
| 收藏 favorites | `POST/DELETE /favorites/{dishId}` `GET /favorites` | 收藏增删查 |
| 历史 history | `POST /history/{dishId}` `GET /history` | 浏览记录 |
| 推荐 recommendations | `POST /recommendations` `GET /recommendations` `POST /{recordId}/feedback` | 智能推荐（结合偏好+预算+忌口+健康摘要）+ 反馈 |
| 健康 health | `POST /health/summary` `GET /health/summary/latest` `GET /health/analysis` `POST /health/auth-status` `POST /revoke-health-auth` | 健康摘要上报、**健康分析报告**（HealthAnalyzer 引擎，评分/评级/建议/关联推荐）、授权状态 |
| 食物识别 food | `POST /food/recognize` | 拍照识食（百度菜品识别兜底本地匹配） |
| 用户 user | `GET/PUT /user/preference` `GET/POST/DELETE /user/avoid` | 饮食偏好、忌口管理 |

**健康分析引擎规则**（HealthAnalyzer）：步数/睡眠/心率/压力/活动量逐项评级 → 综合评分（≥85 优秀 / ≥70 良好 / ≥55 一般 / 其余待改善）→ 针对性饮食建议 → 复用推荐引擎出关联菜品。

**15 张业务表**：`sh_user / sh_user_auth / sh_user_preference / sh_user_avoid / sh_health_auth / sh_health_summary / sh_category / sh_tag / sh_dish / sh_dish_tag / sh_recommendation_rule / sh_recommendation_record / sh_recommend_feedback / sh_favorite / sh_browse_history`。

| `SHANHENG_BAIDU_API_KEY` | 百度菜品识别 API Key | ⬜ 空，待用户开通 |

> 后端代码里所有密钥都通过 `${环境变量:默认空}` 读取，未配置时返回明确业务错误而非崩溃（如华为登录未配置返回「client_id/client_secret 为空」，百度识别未配置返回「菜品识别未配置」）。

## 四、次数限制 + 开源免费替代方案

> 结论：**当前第三方调用对"毕设/上线初期"体量，全部免费额度内够用；若想彻底零依赖，下表给出可落地的开源替代。**

| 服务 | 免费额度 / 限制 | 开源·免费替代方案 | 建议 |
| --- | --- | --- | --- |
| 百度 AI 菜品识别 | 个人实名后免费额度（日几百次），超量按次付费（约几分钱/次） | ① 百度开源 **PaddleClas** 菜品识别模型，本地 Docker 部署，免费不限次（需服务器算力）；② 完全不用云识别时，退回「手动选分类+菜名」 | 毕设直接用免费额度即可；PaddleClas 仅在要「0 成本+不限次」且愿投入部署时选 |
| USDA FoodData Central | `DEMO_KEY` 免费但限次（日 30~50 次）；注册免费 key 提额到日 1000 次 | ① **Open Food Facts**（开源开放数据库，免费 API，含部分中文）；② **中国食物成分表**（中国疾控中心公开数据，可导入本地 `sh_dish` 营养字段，一次导入永久离线用） | 建议后续把「中国食物成分表」导入本地库，营养补全即可零外部依赖 |
| 华为 Account Kit | **免费，不计次、不按量收费** | 无（系统级能力） | 无需替代 |
| 华为 Health Service Kit | **免费，不计次**；受限权限是企业资质「门槛」而非「费用」 | 无开源替代（手表数据只能走品牌官方 SDK） | 无需替代；受限数据未过审时用手动录入兜底 |
| Cloudflare R2（图片存储，预留未接入） | 免费 10GB + 月 100 万次读写 + 无流量费 | **MinIO**（开源 S3 兼容，可装在同一台服务器自托管，免费无限） | R2 免费额度已足够；不想多注册账号可切 MinIO |

## 五、手表 / 健康数据与 App 对接现状（为什么手机目前看不到）

### 5.1 现在的真实进度

| 环节 | 状态 |
| --- | --- |
| 前端同步代码（`HuaweiHealthService.ets`） | ✅ 已写，但**只覆盖「一般权限」数据：步数 / 卡路里 / 距离** |
| 后端摘要上报 + 健康分析 | ✅ 已完成（`sh_health_summary` + `HealthAnalyzer` + `/health/analysis`） |
| 手动健康录入兜底 | ✅ 已完成（可在健康页手动填步数/睡眠时长/心率/压力/活动量，同样能出分析报告） |
| 手表心率 / 睡眠 / 压力 / 血氧（受限权限） | ⬜ **代码尚未接**（原计划企业资质到位后再加） |
| AGC「运动健康服务」开通 + 重新生成签名 profile | ⬜ **未做**（这是当前看不到数据的根本原因） |

### 5.2 为什么手机上现在看不到数据

按顺序有 4 个前置条件，**前两个还没完成**：

1. **AGC 未开通「运动健康服务」**：你当前签名 profile 里 `app-services-capabilities` 只有 Push/地图/安全检测，**没有 Health Kit 能力**。不开通，`healthStore.init/aggregateData` 一调就会失败。
2. **签名 profile 未重新生成**：开通服务后必须在 DevEco「Project Structure → Signing Configs」重新下载 profile 覆盖本机，能力才会注入 App。
3. **真机需登录华为账号 + 健康数据源**：手表数据要先通过蓝牙同步到「华为运动健康 App」，Health Kit 才能从云端/本地读到；没戴手表的手机，步数来自手机计步，心率/睡眠/压力基本为空。
4. **首次点「同步」会弹华为授权框**：拒绝授权则读不到（当前是「手动录入」兜底）。

### 5.3 数据链路（走通后的样子）

```
手表/手环 ──蓝牙──▶ 华为运动健康 App ──▶ Health Kit 云端
                                            │ App 授权后读取
                                            ▼
                    App(HuaweiHealthService) 读步数/卡路里/距离(一般权限)
                                            │ 融成摘要 source=HEALTH_KIT
                                            ▼
                    后端 /app/v1/health/summary ──▶ HealthAnalyzer ──▶ 健康分析报告
```

### 5.4 下一步要做的（让手表数据真实可见）

1. AGC 开通「运动健康服务」→ 申请数据权限（一般权限直接可用；受限权限：心率/睡眠/压力，你企业资质已到位，可一并发起审核）。
2. DevEco 重新生成签名 profile。
3. （代码侧）如要读手表心率/睡眠/压力，需扩展 `HuaweiHealthService` 增加受限权限数据类型的读取（审核通过后）。
4. 真机登录华为账号 + 连接手表，点「同步华为运动健康」验证。
