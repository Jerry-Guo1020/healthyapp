# 15 · 后端模块实现设计（shanheng-app）

> 本文是 `04-技术架构设计.md` 与 `06-API接口设计.md` 的落地实现规范，指导 `api/ruoyi-modules/shanheng-app` 编码。

## 一、模块定位

| 端 | 路径前缀 | 认证 | 账号表 |
| --- | --- | --- | --- |
| 管理端 | `/shanheng/**`（若依体系） | sa-token（管理员） | `sys_user` |
| App 端 | `/app/v1/**` | 独立 JWT（App 用户） | `sh_user` |

两类账号、两条认证体系完全隔离，互不影响。

## 二、分层与包结构（对齐 RuoYi）

```
org.dromara.shanheng
├── controller        # App 接口控制器（/app/v1/**）
├── controller.admin  # 管理端业务 CRUD（/shanheng/**，@SaCheckPermission 保护）
├── domain
│   ├── bo            # 请求体/查询对象
│   └── vo            # 响应体
├── entity            # 实体（映射 sh_* 表）
├── mapper            # BaseMapperPlus 接口
├── service           # 业务接口
│   └── impl          # 业务实现
├── config            # App JWT 拦截器、SaToken 权限放行等配置
└── constant          # 常量与枚举
```

## 三、实体基类约定（关键）

| 表类型 | 继承 | 原因 |
| --- | --- | --- |
| 管理侧：`sh_category/sh_tag/sh_dish/sh_recommendation_rule` | `BaseEntity` | 管理端登录态会自动填充 `create_by/update_by/create_dept`，这些表已补齐对应列 |
| App 侧：其余 `sh_*` 表 | 不继承，独立 `@Data` 类 | 无登录态时框架会把 `create_by/update_by/create_dept` 填 `-1`，而 App 表无这些列会报错；时间字段靠 DB `DEFAULT CURRENT_TIMESTAMP` 兜底 |

App 侧实体时间字段不必标 `fill`，插入时置 null 即由数据库默认值生成。

## 四、通用约定

- 返回：`R<T>`（`org.dromara.common.core.domain.R`），分页 `TableDataInfo<T>`。
- 主键：雪花 ID（`@TableId(value = "id")`，全局 ASSIGN_ID）。
- 逻辑删除：`deleted` 字段 `@TableLogic`（1 删 / 0 存）。
- 校验：`@Validated` + 分组（AddGroup/EditGroup/QueryGroup）。
- 幂等：写接口 `@RepeatSubmit`。

## 五、App 端认证方案（P0 简版）

1. **验证码登录**：`send-code` 发验证码存 Redis（60s 防重发、5 分钟有效）；`login-by-code` 校验后签发 JWT。
2. **游客登录**：`guest` 用 deviceId 直接签发 JWT（`isGuest=1`）。
3. **JWT 载体**：`sh_user` 的 id + isGuest，Redis 里存 session 便于吊销。
4. **华为 Account Kit**：`huawei-login` 预留（code 换身份后合并账号），详见 `07`。
5. 拦截器：`config` 下注册 App JWT 拦截器，仅拦 `/app/v1/**`，放行 auth 接口。

## 八、编码检查点

1. App 实体不引 `BaseEntity`；管理侧实体引 `BaseEntity`。
2. 每张 `sh_*` 表对应 entity 字段与本表列严格一致。
3. App 接口不手写 sa-token 检查，走 JWT 拦截器；管理接口 `@SaCheckPermission`。
4. 每完成一个模块在 `tasks/` 追加日志。
