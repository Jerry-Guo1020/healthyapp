# 08 · 实体设备测试方案

## 一、测试目标

验证真实设备链路：华为手机 + 华为手表/手环 + 华为运动健康 App + 膳衡 App + 后端，确保：
1. 账号登录链路可用。
2. 健康数据授权、读取、摘要上传、推荐展示链路可用。
3. 异常场景兜底正确。

---

## 二、测试环境

| 项 | 要求 |
| --- | --- |
| 测试手机 | 华为手机（HarmonyOS NEXT / API 24 真机） |
| 手表/手环 | 华为手表或手环，已充满电 |
| 华为运动健康 App | 最新版，已登录华为账号 |
| 膳衡 App | debug 签名测试包 |
| 后端 | api（8080）+ maneger-web（若依 8081）+ MySQL + Redis 测试环境 |
| 网络 | 手机与后端可互通（同一局域网或公网测试域名） |
| 数据准备 | 管理端已录入 ≥ 20 条测试菜品，配置好推荐规则 |

---

## 三、正常流程测试

### 测试用例 T1：完整链路（手表用户）

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 手机登录华为账号 | 登录成功 |
| 2 | 华为运动健康 App 绑定手表 | 绑定成功 |
| 3 | 佩戴手表产生步数/睡眠/心率/压力数据 | 运动健康 App 有数据 |
| 4 | 在运动健康 App 确认数据已同步 | 数据可见 |
| 5 | 膳衡 App 发起华为账号登录 | 成功进入 App（或降级验证码登录） |
| 6 | App 请求 Health Kit 授权 | 弹出授权页 |
| 7 | 用户同意健康数据授权 | 授权成功 |
| 8 | App 读取健康数据 | 成功读取步数/睡眠等 |
| 9 | 上传健康摘要到后端 | 后端 `sh_health_summary` 有记录 |
| 10 | 后端生成饮食推荐 | 返回推荐 + 理由 |
| 11 | 前端展示推荐结果 | 展示菜品、理由、健康建议 |

### 测试用例 T2：无手表用户流程

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 不登录（游客） | 可浏览首页/分类/菜品 |
| 2 | 点击"午餐" | 展示午餐菜品列表 |
| 3 | 搜索"鸡" | 返回相关菜品 |

| 6 | 生成推荐（无健康数据） | 返回常规推荐 |

## 四、异常场景测试

| 编号 | 场景 | 操作 | 预期兜底 |
| --- | --- | --- | --- |
| E1 | 用户没有手表 | 无手表直接使用 | 菜单功能正常，健康入口提示授权但非必需 |
| E2 | 未安装华为运动健康 App | 点击健康授权 | 引导安装；未安装则禁用健康入口 |
| E3 | 用户拒绝健康授权 | 授权页点拒绝 | 进入菜单功能，推荐为常规推荐 |
| E4 | 只授权部分数据 | 只勾选步数 | 仅用步数摘要，其他字段空，推荐跳过相关规则 |
| E5 | 手表未同步数据 | 手表断开同步 | 读取为空 → 用最近摘要；无则提示暂无数据 |
| E6 | 无睡眠数据 | 授权但无睡眠记录 | 睡眠字段空，跳过睡眠规则 |
| E7 | 无压力数据 | 授权但无压力记录 | 压力字段空，跳过压力规则 |
| E8 | 网络异常 | 断网操作 | App 提示网络错误，支持重试，不崩溃 |
| E9 | 华为账号未登录 | 发起华为登录 | 引导登录华为账号，失败可验证码登录 |
| E10 | 一键登录失败 | 触发一键登录失败 | 降级普通登录 → 验证码登录 |
| E11 | 后端接口异常 | 后端 500/超时 | App 友好提示 + 重试 + 本地缓存兜底 |
| E12 | 用户取消授权后再次进入 | 取消授权 | 健康摘要不再使用，推荐回归常规 |
