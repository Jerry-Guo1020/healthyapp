---

## 一、项目一句话定位

膳衡是一个**基于华为生态（手机 + 手表 + 运动健康）的健康饮食决策助手**：
- 没有手表：正常使用「菜单发现 + 场景推荐」，解决"今天吃什么"。
- 有手表：授权读取运动健康数据后，获得更个性化的饮食建议。
- 健康数据是**推荐增强能力**，不是使用门槛；饮食建议是**生活辅助**，不是医疗诊断。

## 二、关键决策速览（务必先读）

| 决策项 | 结论 | 说明 |
| --- | --- | --- |
| 数据库 | **MySQL 8.0**（utf8mb4） | 若依原生支持、国内生态成熟、Docker 镜像稳定；详见 `04-技术架构设计.md` |
| 对象存储 | **Cloudflare R2** | 免费 10GB、无流量费、S3 兼容 API，适合菜品图片 |
| 后端 | `api/` = 统一后端（**RuoYi-Vue-Plus** 框架 + 膳衡 App 业务模块，Boot 3 / JDK 17） | **一个 Spring Boot** 同时服务 App 端与管理端 |
| 管理平台 | `maneger-web/` = 若依管理端前端（Vue） | 对接 `api` 后端 |
| 后端数量 | **只保留一个 Spring Boot**，表前缀隔离：若依 `sys_*`，膳衡业务 `sh_*` | 避免双后端双写，见 `13-管理后台平台方案.md` |
| CI/CD | GitHub Actions + Docker Compose 部署到云服务器 | 见 `14-CICD与部署方案.md` |
| 华为登录 | Account Kit（一键登录仅企业开发者，需降级方案） | 见 `07-华为服务接入方案.md` |
| 健康数据 | Health Service Kit（受限权限需审核，后端只存摘要） | 见 `07-华为服务接入方案.md` |

## 五、协作规范（企业级开发约定）

1. **先读日志再动手**：每次新 AI 会话先读 `tasks/` 目录最新日志，了解进度和上下文。
2. **一次只做一个任务**：每次改动聚焦一个模块，完成后在 `tasks/` 追加日志。
3. **日志格式**：`YYYY-MM-DD-序号-任务标题.md`，内容包含：任务目标、改动的文件、关键决策、遗留问题、下一步建议。
4. **代码与文档同步**：改了表结构必须同步 `doc/05-数据库设计.md`，改了接口必须同步 `doc/06-API接口设计.md`。
5. **提交规范**：Git 提交信息使用 Conventional Commits（`feat:` / `fix:` / `docs:` / `refactor:` / `ci:` 等）。
6. **分支策略**：`main`（稳定）、`dev`（开发）、`feat/xxx`（功能分支），PR 合并。
